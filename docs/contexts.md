# Опис контекстів баз даних та архітектурних рішень (FitPulse)

## 1. Booking & Payments Context (Контекст Бронювань та Платежів)

**База даних:** `fitpulse_booking_db` (PostgreSQL)

Цей контекст відповідає за транзакційний процес бронювання тренувань, керування підписками (абонементами) клієнтів, обробку фінансових транзакцій та журнал дій клієнтів.

### Основні агрегати та сутності:

* **Client (Кореневий агрегат):** Містить персональні дані клієнта (`full_name`, `email`, `phone`). Включає версіонування (`version`) для оптимістичного блокування, аудитні поля (`created_by`, `updated_by`) та прапорець `is_deleted` для м'якого видалення (Soft Delete).
* **Subscription & ClientSubscription:** Довідник доступних типів підписок та проміжна сутність M:N, що фіксує термін дії та статус придбаного абонемента.
* **Booking:** Транзакційна сутність бронювання занять. Містить денормалізоване ім'я тренера (`trainer_name`) та м'який ключ `schedule_slot_id` для збереження автономності від контексту розкладу.
* **PaymentRecord (Сутність 1:1 з Booking):** Зберігає фінансовий знімок (суму, спосіб оплати, статус транзакції). Зв'язана 1:1 з `Booking` через спільний первинний/зовнішній ключ (`booking_id`), де PK залежної таблиці є водночас її FK.

## 2. Catalog & Schedule Context (Контекст Каталогу та Розкладу)

**База даних:** `fitpulse_catalog_db` (PostgreSQL)

Цей контекст відповідає за ведення обліку тренерського складу, спортивних залів, категорій тренувань та формування гнучкого розкладу занять.

### Основні агрегати та сутності:

* **Trainer (Кореневий агрегат):** Базова інформація про тренера (`full_name`, `email`, `specialization`).
* **TrainerDetails (Зв'язок 1:1):** Сутність з детальною інформацією (податковий номер `tax_number`, стаж `experience_years`, біографія).
* **TrainingType & TrainerTrainingTypes (M:N з власними полями):** Категорії тренувань та проміжна сутність, що містить власні додаткові поля (`assigned_at` — дата призначення, `qualification_level` — рівень кваліфікації).
* **GymHall:** Довідник спортивних залів із зазначенням їх місткості (`capacity`).
* **ScheduleSlot (Слоти розкладу):** Сутність 1:N, яка пов'язує тренера, зал, часовий інтервал проведення тренування та ціну. Містить складені індекси для оптимізації вибірки вільного часу.

## 3. Feedback & Activity Context (Контекст Відгуків та Журналів Активностей)

**База даних:** `fitpulse_reviews_db` (MongoDB)

Цей контекст відповідає за збереження відгуків про тренерів, аналітику задоволеності клієнтів та довільні журнали фізичної активності.

### Основні колекції та рішення:

* **reviews (Гібридний підхід):** Використовує Referencing (`trainer_id`, `client_id`) для зв'язку з іншими контекстами та Embedding (вкладений масив `comments`) для швидкого читання коментарів без додаткових міжсервісних запитів.
* **client_activity_logs (Гнучка NoSQL структура):** Дозволяє зберігати довільні набори полів під різні види тренувань (силові, кардіо, йога).
* **trainer_ratings (Денормалізована агрегація):** Агрегована статистика середнього рейтингу тренерів для швидкого відображення в каталозі.
